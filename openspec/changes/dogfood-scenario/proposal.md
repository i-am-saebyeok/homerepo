# Proposal

## Why

도구의 단위 시험은 가짜 Herdr와 가짜 런타임으로 돈다. 사용자가 겪는 것은 그 바깥에 있다. 빈 폴더에서 Home을 만들고, 에이전트에게 말로 일을 맡기고, 에이전트가 스킬과 도움말만으로 스레드와 worktree를 다루는 흐름이다. 이 흐름을 손으로 한 번 돌렸을 때 단위 시험에 없던 문제가 드러났다. 선언 파일의 형식을 알려 주는 곳이 없었다. 손으로 돌리는 시험은 다시 하지 않게 되므로, 같은 흐름을 명령 하나로 되풀이할 수 있게 한다.

## What Changes

- 사용자가 말하는 수준으로 쓴 시나리오 지시문을 저장소에 둔다. 첫 시나리오는 새 저장소를 만들어 Home에 선언하고 worktree에서 첫 변경을 올리는 흐름이다.
- 실행기가 깨끗한 시험용 Home을 차리고, 작업 중인 코드로 빌드한 `homerepo`를 쓰게 하고, Herdr 탭에서 실제 런타임의 코디네이터를 띄워 시나리오를 보낸다. 스레드가 생기면 사람 대신 시작하라는 한 줄을 보낸다.
- 실행기가 끝난 뒤의 상태를 확인하고 결과를 알린다. 확인 가운데 하나라도 실패하면 0이 아닌 코드로 끝난다.
- 원격은 로컬의 빈 저장소를 쓴다. 호스팅 서비스에는 아무것도 만들지 않는다.
- `thread create`가 탭의 셸이 준비되지 않아 거절된 포크 명령을 정해진 시간 안에서 다시 보낸다.

## Capabilities

### New Capabilities

- `dogfood`: 실제 런타임과 멀티플렉서로 사용자의 흐름을 되풀이해 돌리는 시나리오 시험.

### Modified Capabilities

- `thread`: 요구사항 "세션이 준비되기를 기다리지 않는다"에, 탭의 셸이 아직 명령을 받지 못할 때 포크 명령을 다시 보낸다는 것을 더한다. 시나리오 시험을 Codex로 처음 돌렸을 때 드러났다. 탭을 만든 직후에는 셸이 1024바이트를 넘는 줄을 받지 못하고, 2초쯤 뒤에는 받는다.

## Impact

- 실행기와 시나리오가 들어갈 새 폴더. 배포하는 `homerepo` 실행 파일에는 들어가지 않는다.
- 실행에는 Herdr, 로그인된 런타임, Git이 필요하다. CI에서는 돌지 않는다.
