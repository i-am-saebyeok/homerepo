# Design

## Context

스레드는 실제 에이전트 세션의 포크이고 Herdr의 탭에 뜬다. 그래서 끝에서 끝까지의 흐름은 실제 런타임과 Herdr 없이는 돌릴 수 없다. 동기는 proposal.md의 Why를 본다.

## Goals / Non-Goals

**Goals:**

- 사용자의 흐름 하나를 명령 하나로 되풀이해 돌린다.
- 도구의 동작으로 가를 수 있는 것은 실행기가 확인한다.
- 에이전트가 어디서 헤맸는지 사람이 읽을 수 있게 남긴다.

**Non-Goals:**

- CI에서 돌리는 것.
- 호스팅 서비스에 저장소를 만드는 흐름. 필요해지면 시나리오를 따로 더한다.
- 런타임이 처음 보는 폴더에 띄우는 신뢰 창을 대신 답하는 것.
- 에이전트가 남긴 결과 문서의 내용을 판정하는 것.

## Decisions

### 시나리오는 사용자가 말하는 수준으로 쓴다

지시문에는 이루려는 일만 적는다. 명령의 이름, 선언 파일의 필드, 인증 요령처럼 사용자가 알려 주지 않을 답은 적지 않는다. 답을 적으면 시험은 통과하지만 사용자가 막히는 곳이 가려진다. 에이전트는 설치된 스킬과 도움말로 길을 찾는다.

### 시험용 Home의 자리는 고정한다

실행기는 인자로 받은 루트 폴더 아래의 같은 경로에 Home을 차리고, 실행할 때마다 그 내용을 비운다. 런타임은 폴더의 신뢰를 경로로 기억하므로 사람이 처음 한 번만 답하면 된다. 새 저장소와 원격으로 쓸 빈 저장소도 그 루트 아래에 만든다. 루트 밖은 건드리지 않는다.

### 접근 범위는 루트 폴더 전체로 연다

시험용 Home은 추가 폴더 인자를 끄고(`attach: false`), 런타임의 설정으로 루트 폴더를 연다. 새 저장소를 만드는 흐름은 아직 없는 폴더까지 열려 있어야 하고, 인자로 붙인 폴더에는 런타임이 확인 창을 띄워 사람 없이 돌 수 없기 때문이다.

### 작업 중인 코드로 빌드한 실행 파일을 쓴다

실행기는 저장소의 현재 코드로 `homerepo`를 빌드하고, 띄우는 세션의 `PATH` 앞에 둔다. 기기에 설치된 실행 파일로 돌면 고친 코드를 시험하지 못한다.

### 원격은 로컬의 빈 저장소다

도구가 요구하는 것은 선언한 브랜치가 있는 원격뿐이다. 로컬의 빈 저장소로도 도구의 동작은 같게 확인되고, 인증과 뒷정리가 필요 없다.

### 끝은 에이전트의 상태로 안다

실행기는 스레드의 창이 일을 마친 상태가 되기를 Herdr로 기다린다. 시간 제한을 넘기면 실패로 알린다. 에이전트가 따로 알리게 하지 않는다. 알림을 잊은 것과 일이 실패한 것을 가를 수 없기 때문이다.

### 끝난 뒤의 탭과 폴더는 남긴다

사람이 화면과 파일을 읽을 수 있게 남기고, 다음 실행을 시작할 때 지운다.

## Risks / Trade-offs

- [같은 시나리오에서도 에이전트가 다른 길로 간다] → 확인이 실패하면 실행기는 에이전트의 결과 문서와 창의 화면을 가리킨다. 도구의 문제인지는 사람이 가른다.
- [돌릴 때마다 토큰과 시간이 든다] → 커밋마다 돌리지 않는다. 스레드, worktree, 설치되는 스킬을 바꿨을 때 돌린다.
- [런타임의 화면이 바뀌면 확인 창을 알아보지 못한다] → 화면의 글이 아니라 Herdr가 알려 주는 에이전트의 상태로 가른다.
