# Spec Delta

## ADDED Requirements

### Requirement: 시나리오 실행
실행기는 받은 루트 폴더 아래의 고정된 경로에 시험용 Home을 새로 차리고, Herdr의 새 탭에서 지정한 런타임의 코디네이터 세션을 띄워 시나리오의 지시문을 보내야 한다(SHALL). Home은 비우고 `git init`과 `homerepo init`을 한 상태로 시작한다. 띄운 세션은 저장소의 현재 코드로 빌드한 `homerepo`를 쓴다. 루트 폴더 밖에는 파일을 만들거나 지우지 않는다.

#### Scenario: 처음 돌린다
- **WHEN** 빈 루트 폴더와 런타임 `claude`, 시나리오 `new-repository`로 실행한다
- **THEN** 루트 아래에 Home이 차려지고, 새 탭의 코디네이터가 그 시나리오의 지시문을 받는다

#### Scenario: 다시 돌린다
- **WHEN** 앞선 실행의 Home, 저장소, 탭이 남아 있는 루트로 다시 실행한다
- **THEN** 앞선 실행의 탭이 닫히고 폴더가 비워진 뒤 같은 경로에서 새로 시작한다

#### Scenario: 작업 중인 코드를 쓴다
- **WHEN** 기기에 설치된 `homerepo`와 저장소의 코드가 다르다
- **THEN** 띄운 세션에서 실행되는 `homerepo`는 저장소의 코드로 빌드한 것이다

#### Scenario: 필요한 것이 없다
- **WHEN** Herdr 밖에서 실행했거나, 런타임의 실행 파일이나 없는 시나리오 이름을 줬다
- **THEN** 아무것도 만들지 않고 무엇이 없는지 알리며 0이 아닌 코드로 끝난다

### Requirement: 스레드를 시작시킨다
실행기는 시나리오가 만든 스레드의 탭이 생기면 그 창에 시작하라는 한 줄을 보내야 한다(SHALL). 사람이 그 탭에서 말을 거는 일을 대신하는 것이다. 정해진 시간 안에 스레드가 생기지 않으면 실패로 알린다. 코디네이터나 스레드의 런타임이 뜨지 않거나 뜨자마자 끝나 셸로 돌아가면 시간 제한까지 기다리지 않고 실패로 알린다. 확인을 기다리며 멈췄거나 런타임이 끝나 실패할 때는 그 창의 보이는 화면 끝 줄을 함께 보인다. 화면의 글로 무엇을 묻는지 판정하지는 않는다.

#### Scenario: 스레드가 생긴다
- **WHEN** 코디네이터가 `homerepo thread create`로 스레드를 만든다
- **THEN** 실행기가 그 스레드의 창에 한 줄을 보내고, 스레드가 일을 시작한다

#### Scenario: 스레드가 생기지 않는다
- **WHEN** 정해진 시간이 지나도록 스레드의 기록이 없다
- **THEN** 실행기는 스레드가 만들어지지 않았다고 알리고 코디네이터의 창을 가리킨다

#### Scenario: 런타임이 뜨자마자 끝난다
- **WHEN** 코디네이터나 스레드의 창에서 런타임이 오류를 찍고 끝나 셸로 돌아간다
- **THEN** 실행기는 시간 제한까지 기다리지 않고, 런타임이 끝났다는 것과 그 창의 보이는 화면 끝 줄을 알리며 0이 아닌 코드로 끝난다

### Requirement: 결과 확인
실행기는 스레드의 창이 일을 마친 상태가 된 뒤 아래를 확인하고, 각 확인의 통과와 실패, 걸린 시간, 남겨 둔 Home과 창의 위치를 출력해야 한다(SHALL). 하나라도 실패하거나 시간 제한을 넘기면 0이 아닌 코드로 끝난다. 탭과 폴더는 지우지 않는다.

| 확인 | 통과의 기준 |
| --- | --- |
| 스레드가 뜸 | 스레드의 창이 확인을 기다리는 상태로 멈추지 않고 입력을 받았다 |
| 저장소 선언 | `homerepo repo list`에 새 저장소가 있고 clone이 있다 |
| worktree | 그 저장소에 스레드 이름의 worktree와 브랜치가 있다 |
| 원격 | 원격에 스레드 이름의 브랜치가 있고 기본 브랜치에 없는 커밋이 있다 |

#### Scenario: 모두 통과한다
- **WHEN** 스레드가 새 저장소를 만들어 선언하고 worktree에서 커밋을 올린 뒤 멈춘다
- **THEN** 네 확인이 모두 통과로 출력되고 실행기는 0으로 끝난다

#### Scenario: 확인 하나가 실패한다
- **WHEN** 스레드가 멈췄는데 원격에 스레드 이름의 브랜치가 없다
- **THEN** 그 확인이 실패로 출력되고, 실행기는 Home과 창의 위치를 알리며 0이 아닌 코드로 끝난다

#### Scenario: 스레드가 확인 창에서 멈춘다
- **WHEN** 스레드의 창이 뜨자마자 확인을 기다리는 상태가 된다
- **THEN** "스레드가 뜸"이 실패로 출력되고, 실행기는 그 창의 보이는 화면 끝 줄을 보이며 그 창에 키를 보내지 않는다

#### Scenario: 시간 제한을 넘긴다
- **WHEN** 정해진 시간이 지나도록 스레드가 일을 마치지 않는다
- **THEN** 실행기는 기다리기를 멈추고, 그때까지의 확인 결과와 함께 시간 제한을 넘겼다고 알린다

### Requirement: 시험용 Home의 구성
실행기는 시험용 Home에 도구가 추가 폴더 인자를 붙이지 않게 하는 설정을 두고, 런타임의 설정이나 인자 묶음으로 루트 폴더를 세션에 열어야 한다(SHALL). 원격으로는 루트 아래에 만든 로컬의 빈 저장소를 지시문에 알려 준다. 호스팅 서비스에는 아무것도 만들지 않는다.

#### Scenario: 도구가 폴더를 붙이지 않는다
- **WHEN** 시험용 Home에서 스레드가 만들어진다
- **THEN** 스레드의 포크 명령에 저장소의 `.worktrees`를 가리키는 추가 폴더 인자가 없고, 스레드는 루트 아래의 새 폴더를 만들 수 있다

#### Scenario: 원격이 로컬에 있다
- **WHEN** 시나리오 `new-repository`를 실행한다
- **THEN** 지시문이 알려 주는 원격은 루트 아래의 빈 저장소이고, 실행 중 네트워크의 호스팅 서비스에 저장소가 생기지 않는다
