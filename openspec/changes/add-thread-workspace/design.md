# Design

## Context

구조는 Home Repo 패턴을 따른다. 하네스(지침, 에이전트, 스킬)는 Home 저장소에 있고, 코드 저장소는 각자 clone 하나씩 따로 있다. 세션은 Home에서 시작한다.

아래 동작은 macOS에서 Claude Code 2.1.331, Codex 0.172.0, Herdr 0.9.5로 손으로 이어 붙여 확인했다.

- Claude Code는 `--resume <세션 ID> --fork-session`으로, Codex는 `codex fork <세션 ID>`로 대화를 포크한다. 부모가 도구를 실행하는 도중에도 포크된다.
- 세션 안에서 실행한 명령은 환경 변수로 런타임과 세션 ID(`CLAUDECODE`, `CLAUDE_CODE_SESSION_ID`)와 Herdr의 창(`HERDR_PANE_ID`, `HERDR_WORKSPACE_ID`)을 안다.
- Herdr는 포커스 없이 탭을 만들고, 에이전트가 준비될 때까지 기다리고, 프롬프트를 제출하고, 확인 창에서 멈춘 것을 `blocked`로 알린다.
- `<clone>/.worktrees`만 추가 폴더로 붙인 세션은 그 안의 worktree를 고치고 커밋한다. 원래 작업 폴더는 읽을 수 있다.
- `*` 한 줄짜리 `.gitignore`를 둔 폴더 안의 worktree는 원래 clone의 `git status`와 파일 검색에 나오지 않는다.

## Goals / Non-Goals

**Goals:**

- 한 Home에서 스레드를 만들어 worktree에서 일하고 닫는 흐름을 명령으로 돌린다.
- 사람이 쓰는 탭과 원래 작업 폴더를 건드리지 않는다.
- 하네스에 관여하지 않는다. 역할, 방법론, 모델, 권한 수준은 사용자가 정한다.

**Non-Goals:**

- 다른 벤더의 런타임으로 넘기는 스레드
- Herdr가 아닌 멀티플렉서
- 병합, 브랜치 정리, push
- 스레드에서 다시 포크하기
- 패키지 배포와 자동 갱신

## Decisions

### 언어는 Go, 실행 파일 하나

훅이 자주 부를 조회 명령(`repo path`)이 있어 시작 시간이 짧아야 하고, 쓰는 사람에게 런타임을 요구하지 않는다. Node는 같은 기기에서 시작에 0.1초쯤 걸렸다.

### 세션은 Home에서 시작하고 `.worktrees`만 붙인다

worktree에서 세션을 시작하면 하네스를 읽는 것이 런타임의 상위 폴더 탐색에 달린다. Home에서 시작하면 그 의존이 없다. clone 전체가 아니라 `.worktrees`만 붙이면 원래 작업 폴더의 편집은 런타임의 권한 확인에 걸린다.

대안으로 clone 전체를 붙이는 방법은 단순하지만 원래 작업 폴더를 묻지 않고 고칠 수 있어 쓰지 않는다.

### worktree는 clone 안의 `.worktrees/<스레드>`

clone의 자리만 알면 worktree의 자리가 정해지고, 세션을 띄울 때 붙일 폴더가 저장소마다 하나로 고정된다. worktree의 목록은 저장하지 않고 `git worktree list`에서 읽는다.

### 런타임과 멀티플렉서는 설정이 아니라 환경에서 읽는다

한 사람이 두 런타임을 함께 쓴다. 스레드는 부모와 같은 런타임이므로 호출한 자리의 환경 변수가 정답이다. 런타임마다 다른 것(포크 명령, 인자)은 런타임 어댑터 하나에 모은다.

### 스레드의 정체는 환경 변수로 넘긴다

스레드 세션을 띄울 때 탭의 환경에 `HOMEREPO_THREAD=<이름>`을 넣는다. `workspace` 명령은 이 값을 읽는다. 값이 없으면 `--thread`를 요구한다.

### 스레드의 기록은 `.homerepo/threads/<이름>.json`

이름, 런타임, 탭 ID, 만든 시각을 적는다. worktree는 적지 않는다. 탭이 사라졌으면 목록에 "탭 없음"으로 표시한다.

### 원격은 이름이 아니라 주소로 찾는다

사람마다 `origin`이 가리키는 곳이 다를 수 있다. `homerepo.yaml`의 주소와 같은 원격을 clone에서 찾아 그 원격의 기본 브랜치에서 갈라진다. 찾지 못하면 멈추고 알린다.

### 스킬은 `.agents/skills/homerepo-thread/`에 두고 커밋한다

OpenSpec이 스킬을 두는 방식과 같다. `.claude/skills`가 같은 폴더를 가리키지 않으면 스킬별 링크를 만든다. 본문은 명령과 안내 한 줄만 담는다. 사람은 말로 시키고 에이전트가 명령을 부른다.

### 확인 창에는 입력을 보내지 않는다

포크된 세션이 신뢰나 승인 창에서 멈추면 사람이 답한다. 그 창의 기본 선택이 무엇이든 시스템이 대신 고르지 않는다.

## Risks / Trade-offs

- [Claude Code가 `.worktrees`를 붙일 때마다 신뢰 창을 띄운다] → 첫 메시지 전에 멈추면 알리고 기다린다. 창을 없애는 방법은 개념 검증에서 찾는다.
- [탭을 만든 직후 에이전트를 띄우면 Herdr가 `agent_pane_busy`를 돌려준다] → 정해진 횟수만큼 다시 시도한다.
- [같은 저장소를 쓰는 스레드끼리 서로의 worktree에 접근할 수 있다] → 붙이는 단위가 `.worktrees` 폴더이기 때문이다. 받아들인다.
- [셸 명령으로는 원래 작업 폴더에 쓸 수 있다] → 기본은 안내다. 강제하려면 사용자가 런타임의 샌드박스를 켠다.
- [`.gitignore`를 읽지 않는 도구가 clone 안의 worktree를 훑을 수 있다] → 실제 저장소에서 써 보고 문제가 되면 worktree의 자리를 설정으로 연다.
- [환경 변수의 이름과 포크 인자는 런타임의 버전에 달려 있다] → 어댑터 하나에 모으고, 찾지 못하면 추측하지 않고 멈춘다.
- [부모가 도구를 실행하는 도중에 포크하면 포크의 마지막 기록이 끝나지 않은 호출이다] → 첫 메시지가 생성이 끝났다는 것을 알린다. 실제 동작은 개념 검증에서 확인한다.
