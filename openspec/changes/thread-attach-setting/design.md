# Design

## Context

포크 명령의 인자는 런타임의 포크 인자, 저장소마다의 추가 폴더 인자, 사용자가 설정에 적은 인자 묶음의 순서로 만들어진다. 앞의 둘은 도구가 정하고 마지막만 사용자가 정한다. 동기는 proposal.md의 Why를 본다.

## Goals / Non-Goals

**Goals:**

- 세션에 붙는 폴더를 사용자가 전부 정할 수 있게 한다.

**Non-Goals:**

- 어떤 폴더를 붙일지 도구가 정하는 것. 도구는 기본값(worktree) 하나만 안다.
- 런타임의 설정 파일을 도구가 읽거나 쓰는 것.
- 저장소를 새로 만드는 명령.

## Decisions

### 끄는 값 하나만 둔다

붙일 폴더의 목록을 도구의 설정으로 받지 않는다. 인자 묶음이 이미 임의의 인자를 받고 런타임에도 자기 설정이 있어서, 목록을 받으면 같은 것을 적는 자리가 셋이 된다. 도구가 붙이는 것을 끄면 나머지는 그 두 자리로 정할 수 있다.

### 런타임마다 따로 정한다

값은 `runtimes.<런타임>` 아래에 둔다. 런타임마다 폴더를 받는 길이 다르다. 한 런타임은 설정 파일로 붙이고 다른 런타임은 인자로만 받는 사용자가 있다.

### 적지 않은 것과 `false`를 구분한다

`attach`가 없으면 붙인다. 기존 설정 파일이 그대로 동작해야 하기 때문이다. 참과 거짓이 아닌 값은 설정 오류로 알린다.

### 훅이 받는 경로는 그대로다

`HOMEREPO_HOOK_DIRS`는 도구가 인자로 붙였는지와 무관하게 저장소의 `.worktrees` 경로를 담는다. 인자를 끄고 훅에서 그 경로를 런타임의 설정에 적는 사용자에게 필요하다.

## Risks / Trade-offs

- [`attach`를 끄고 폴더를 다른 길로도 붙이지 않으면 세션이 worktree에 접근하지 못하거나 매번 승인을 묻는다] → 도구는 확인하지 않는다. 폴더를 붙이는 길을 도구가 알지 못하기 때문이다.
