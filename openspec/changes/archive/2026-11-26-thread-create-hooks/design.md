# Design

## Context

`thread create`는 요청을 검사하고, worktree를 만들고, 탭을 만들고, 기록을 쓰고, 그 탭의 창에서 포크 명령을 실행한 뒤 바로 끝난다. 띄운 세션에는 입력을 보내지 않는다. 동기는 proposal.md의 Why를 본다.

## Goals / Non-Goals

**Goals:**

- 스레드를 만드는 앞과 뒤에 사용자가 정한 명령을 돌릴 자리를 둔다.
- 그 명령이 스레드와 띄운 창을 가리킬 수 있게 값을 넘긴다.

**Non-Goals:**

- 신뢰 창이나 승인 창을 처리하는 방법. 도구는 런타임의 창을 알지 못하고, 훅이 무엇을 하는지도 알지 못한다.
- worktree를 만들 때나 스레드를 닫을 때의 훅. 쓰임이 생기면 같은 방식으로 더한다.
- 훅을 설치하거나 여러 사람이 나누는 방법.
- 훅의 시간 제한.

## Decisions

### 파일이 있으면 실행한다

`.homerepo/hooks/<이름>`이 있으면 실행하고 없으면 아무 일도 하지 않는다. 설정 파일에 명령을 적는 방식은 고르지 않았다. 명령과 인자를 YAML로 적는 모양을 새로 정해야 하고, 파일은 어떤 언어로 쓰든 그대로 실행되기 때문이다. 파일은 인자 없이 실행한다.

### 개인의 자리에만 둔다

훅은 `.homerepo/` 아래에만 둔다. 이 폴더는 Git에서 빠져 있다. 여러 사람이 나누는 `homerepo.yaml`에서 명령을 읽으면 Home을 받은 사람의 기기에서 남이 적은 명령이 돌게 된다.

### 시점은 앞과 뒤 둘이다

미리 준비하는 일(저장소를 신뢰해 둔다)은 세션을 띄우기 전에 끝나야 하고, 띄운 세션을 다루는 일(창에 답한다)은 띄운 뒤에만 할 수 있다. 자리가 하나면 한쪽만 할 수 있다.

앞의 훅은 요청의 검사가 모두 끝난 뒤, worktree와 탭을 만들기 전에 실행한다. 거절될 요청에는 훅이 돌지 않고, 훅이 실패하면 되돌릴 것이 없다.

### 훅이 끝나기를 기다린다

도구는 훅이 끝날 때까지 기다리고 종료 코드를 본다. 뒤에서 돌릴지는 훅이 정한다. 그래서 훅이 없는 사용자의 `thread create`는 지금과 같은 시간에 끝나고, 훅이 오래 걸리는 사용자는 그만큼 기다린다.

### 값은 환경 변수로 넘긴다

`HOMEREPO_HOOK_`으로 시작하는 환경 변수로 넘긴다. `HOMEREPO_THREAD`는 쓰지 않는다. 그 변수는 스레드 안의 세션이라는 표시이고, 훅은 스레드 밖에서 돈다. 추가 폴더는 여럿이고 경로에 빈칸이 있을 수 있으므로 한 줄에 하나씩 적는다.

### 훅의 출력은 표준 오류로 보낸다

`thread create`의 표준 출력은 스레드의 이름과 탭을 알리는 한 줄이다. 훅의 표준 출력이 거기에 섞이지 않도록 훅의 표준 출력과 표준 오류를 모두 명령의 표준 오류로 보낸다.

## Risks / Trade-offs

- [뒤의 훅이 실패하면 스레드는 이미 떠 있다] → 스레드를 지우지 않는다. 스레드가 만들어졌다는 것과 훅의 종료 코드를 알리고 0이 아닌 코드로 끝난다.
- [실행 권한이 없는 훅 파일] → 조용히 넘어가지 않고 실패한 훅과 같이 다룬다. 훅을 둔 사용자는 그것이 돌았다고 믿기 때문이다.
- [훅이 끝나지 않으면 명령도 끝나지 않는다] → 시간 제한을 두지 않는다. 훅이 얼마나 걸려도 되는지는 사용자가 정한다.
