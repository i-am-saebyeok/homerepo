# Design

## Context

`thread close`는 기록을 읽고, 각 worktree에 커밋하지 않은 변경이 없는지 검사하고, worktree를 해제하고, 기록을 지우고, 탭을 닫는다. 스레드 생성에는 앞과 뒤의 훅이 있다. 동기는 proposal.md의 Why를 본다.

## Goals / Non-Goals

**Goals:**

- 스레드를 닫는 앞과 뒤에 사용자가 정한 명령을 돌릴 자리를 둔다.
- 닫기 전의 훅이 아직 살아 있는 세션을 다룰 수 있게 창을 넘긴다.

**Non-Goals:**

- 런타임의 세션을 끝내거나 보관하는 방법. 도구는 훅이 무엇을 하는지 알지 못한다.
- worktree를 만들거나 해제할 때의 훅.

## Decisions

### 생성의 훅과 같은 방식으로 실행한다

파일이 있으면 실행하고, Home을 현재 폴더로 인자 없이 띄우고, 값을 `HOMEREPO_HOOK_` 환경 변수로 넘기고, 출력을 표준 오류로 보내고, 끝나기를 기다린다. 닫기에만 다른 규칙을 두지 않는다.

### 닫기 전의 훅은 검사 뒤, 해제 앞에서 실행한다

닫을 수 없는 스레드에는 훅이 돌지 않는다. 훅이 세션을 끝낸 뒤에 닫기가 거절되면 세션만 사라지고 스레드가 남기 때문이다. 훅이 실패하면 아직 아무것도 바뀌지 않았으므로 되돌릴 것이 없다.

### 창의 ID는 닫기 전의 훅에만 넘긴다

닫은 뒤에는 창이 없다. 사람이 탭을 먼저 닫은 스레드에는 닫기 전에도 창이 없으므로 그 값을 넘기지 않는다. 탭의 ID는 기록에 있으므로 두 훅에 모두 넘긴다.

### 훅이 세션을 끝내도 탭 닫기는 그대로 한다

닫기 전의 훅이 세션을 끝내면 창에는 셸이 남는다. 도구는 그 뒤에도 탭을 닫는다.

## Risks / Trade-offs

- [닫은 뒤의 훅이 실패하면 스레드는 이미 닫혀 있다] → 스레드가 닫혔다는 것과 훅의 종료 코드를 알리고 0이 아닌 코드로 끝난다.
- [닫기 전의 훅이 끝나지 않으면 스레드를 닫을 수 없다] → 시간 제한을 두지 않는다. 생성의 훅과 같다.
