# Design

## Context

에이전트는 웹 문서가 아니라 설치된 스킬과 명령의 도움말을 읽고 길을 찾는다. 시나리오 시험에서 막힌 곳은 모두 그 두 자리에 답이 없던 곳이다. 동기는 proposal.md의 Why를 본다.

## Goals / Non-Goals

**Goals:**

- 에이전트가 소스를 읽지 않고 스킬과 도움말만으로 저장소를 등록하고, 스레드와 worktree를 다룰 수 있게 한다.

**Non-Goals:**

- 저장소를 지우거나 고치는 명령. 손으로 파일을 고치면 된다.
- 원격 저장소를 만들거나 첫 커밋을 올리는 일. 도구는 무엇이 필요한지만 알린다.
- 이미 설치된 스킬을 바꾸는 명령.

## Decisions

### 등록은 선언 파일에 항목을 더하는 것뿐이다

`repo add`는 clone을 받지 않는다. clone은 지금처럼 `workspace create`가 처음 필요할 때 받는다. 등록과 clone을 나누면 이미 clone이 있는 저장소(새로 만든 저장소처럼)도 같은 명령으로 등록된다.

같은 이름이 이미 있으면 거절한다. 이름의 규칙과 필수 값은 선언 파일을 읽을 때의 검사를 그대로 쓴다. 더한 뒤의 파일은 다시 읽어 검사를 통과해야 한다.

### 기본 브랜치는 원격에서 읽는다

`--branch`가 없으면 `git ls-remote --symref <원격> HEAD`로 원격의 기본 브랜치를 읽는다. 빈 원격처럼 읽을 수 없으면 추측하지 않고 `--branch`를 요구한다.

### 선언 파일은 다시 쓰지 않고 끝에 덧붙인다

사람이 쓴 `homerepo.yaml`에는 주석과 순서가 있을 수 있다. 파일 전체를 YAML 라이브러리로 다시 쓰면 그것이 사라진다. 항목은 `repositories:` 목록의 끝에 같은 들여쓰기로 덧붙인다. 목록이 `repositories: []`처럼 비어 있으면 그 줄을 목록으로 바꾼다. 덧붙일 수 없는 모양이면 파일을 바꾸지 않고 적을 내용을 출력하며 실패한다.

### 도움말은 표준 출력, 사용 오류는 표준 오류

`--help`와 `-h`는 요청한 것이므로 표준 출력에 내고 0으로 끝난다. 인자가 틀렸을 때는 지금처럼 표준 오류에 사용법을 내고 2로 끝난다. 명령마다의 사용법은 지금 전체 사용법에 있는 그 명령의 줄과 각 옵션의 설명이다.

### worktree 경로는 생성의 출력에 붙인다

`thread create`의 첫 줄은 그대로 두고, `--repo`로 만든 worktree마다 한 줄을 더한다. 첫 줄을 읽는 사람과 도구가 깨지지 않게 하기 위해서다.

## Risks / Trade-offs

- [덧붙이기가 사람이 쓴 특이한 모양의 파일을 망가뜨릴 수 있다] → 덧붙인 결과를 다시 읽어 검사하고, 통과하지 못하면 원래 파일을 그대로 둔다.
